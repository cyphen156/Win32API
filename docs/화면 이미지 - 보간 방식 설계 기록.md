# 화면 이미지 - 보간 방식 설계 기록

스프라이트를 화면에 찍을 때 배율과 보간을 어떻게 처리하기로 했는지, 왜 그렇게 했는지, 다른 길을 고르려면 무엇을 바꾸면 되는지의 기록이다.

- 출발점은 2024년 `Animation::render`의 GDI+ `DrawImage`다. #1_14(카메라 분해, 2026-11-02)에서 줌 배율이 월드 변환에 들어간 뒤 줌 인에서 프레임이 18fps까지 떨어졌다.
- 설계와 조건은 사용자(Cyphen)가 정했다. 단계마다 조건표에 값과 출처를 적는다.
- 구현은 AI와 협업했다.
- 측정은 AI가 작성한 임시 측정 빌드(케이스 스위치 + 구간 타이머)로 했다. 그 빌드는 연습 저장소에 있었고 삭제 대상이다. 아래 수치는 모두 그 출력이며, 재현 방법은 [9. 재현](#9-재현)에 적었다.
- 공개 기록: [블로그 537 "지터와 텍스쳐 배율에 의한 프레임 드랍 현상"](https://cyphen156.tistory.com/537). GIF와 비교 캡처는 그 글에 있다.
- 지터(Trouble 1)는 이 문서의 범위 밖이다. 그 결론만 전제로 쓴다. `Graphics(hdc)`가 HDC 변환을 정수로 다시 읽으므로, 변환을 꺼내 `Graphics`에 직접 넘기고 HDC는 잠깐 항등으로 둔다.

## 0. 현재 구현 (HEAD 기준)

### 지형

`Terrain::render`. GDI `StretchBlt`, 모드는 `World::Render`가 건 `COLORONCOLOR`(최근접). HDC 월드 변환(피치·배율)을 그대로 따른다. 불투명이라 알파 합성이 없다.

```cpp
void Terrain::render(HDC hdc)
{
    Texture* texture = tileDefs[(UINT)tileType].tiles[tileIndex].texture;
    HDC textureDC = texture->GetDC();
    StretchBlt(hdc,
        (int)position.x * TILESIZE, (int)position.y * TILESIZE, TILESIZE, TILESIZE,
        textureDC,
        0, 0, texture->Width(), texture->Height(),
        SRCCOPY);
}
```

### 스프라이트

`Animation::render`. GDI+ `DrawImage`, 보간은 기본값(쌍선형). 텍스처 전체가 아니라 불투명 영역 경계 상자만 원본 영역으로 넘긴다. 상자의 왼쪽 위 오프셋을 그리기 위치에 더하므로 캐릭터가 서는 자리는 정사각형 전체를 그릴 때와 같다.

```cpp
void Animation::render(HDC hdc)
{
	if (m_bFinish)
	{
		return;
	}

	Object* pObj = m_pAnimator->GetOwner();
	Vec2D	vCenter = pObj->GetPos() + m_vOffset;

	Texture* currentFrameTex = GetFrame(m_iCurFrame);

	XFORM transform;
	GetWorldTransform(hdc, &transform);
	ModifyWorldTransform(hdc, nullptr, MWT_IDENTITY);
	{
		Graphics graphics(hdc);
		Matrix matrix(transform.eM11, transform.eM12, transform.eM21, transform.eM22, transform.eDx, transform.eDy);
		graphics.SetTransform(&matrix);

		Image* img = currentFrameTex->GetImage();
		REAL width = img->GetWidth(), height = img->GetHeight();
		const RECT& box = currentFrameTex->GetOpaqueBounds();
		REAL boxWidth = (REAL)(box.right - box.left), boxHeight = (REAL)(box.bottom - box.top);
		RectF dest(vCenter.x - width / 2.f + box.left, vCenter.y - height / 2.f + box.top, boxWidth, boxHeight);
		graphics.DrawImage(img, dest, (REAL)box.left, (REAL)box.top, boxWidth, boxHeight, UnitPixel);
	}
	SetWorldTransform(hdc, &transform);
}
```

### 불투명 영역 경계 상자

`Texture::GetOpaqueBounds`. 처음 쓰일 때 알파 > 0인 픽셀의 경계를 한 번 재고 기억한다. 보간 여유로 1픽셀씩 넓힌다. 전부 투명한 프레임이면 전체 사각형으로 되돌린다. `Texture.h`에 `RECT m_opaqueBounds;`(생성자에서 `{}`)와 `const RECT& GetOpaqueBounds();`가 추가됐다.

```cpp
const RECT& Texture::GetOpaqueBounds()
{
	if (m_opaqueBounds.right == 0 && m_img != nullptr)
	{
		Bitmap* bitmap = (Bitmap*)m_img;
		int width = (int)bitmap->GetWidth(), height = (int)bitmap->GetHeight();
		Rect whole(0, 0, width, height);
		BitmapData data = {};
		int minX = width, minY = height, maxX = -1, maxY = -1;
		if (bitmap->LockBits(&whole, ImageLockModeRead, PixelFormat32bppARGB, &data) == Ok)
		{
			for (int y = 0; y < height; ++y)
			{
				const BYTE* row = (const BYTE*)data.Scan0 + (size_t)y * data.Stride;
				for (int x = 0; x < width; ++x)
				{
					if (row[x * 4 + 3] != 0)
					{
						if (x < minX) minX = x;
						if (x > maxX) maxX = x;
						if (y < minY) minY = y;
						if (y > maxY) maxY = y;
					}
				}
			}
			bitmap->UnlockBits(&data);
		}
		if (maxX < 0)
		{
			m_opaqueBounds = { 0, 0, width, height };
		}
		else
		{
			m_opaqueBounds = { max(minX - 1, 0), max(minY - 1, 0), min(maxX + 2, width), min(maxY + 2, height) };
		}
	}
	return m_opaqueBounds;
}
```

텍스처 자체의 여백은 잘라내지 않는다. 프레임은 원본 아틀라스에서 동작 범위를 정가운데 앵커 기준 정사각형으로 구운 것이라 프레임마다 오프셋을 들지 않아도 된다. 여백을 자르면 그 규격이 깨져 프레임별 오프셋 데이터와 전체 재구움이 필요하다. 상자는 그리기 시점에만 쓴다.

### 컬링

`Scene::render`. 카메라 시야(`GetViewArea`, 바닥 좌표)를 타일 한 칸(`TILESIZE` = 120)만큼 넓힌 사각형에 오브젝트 발 좌표(`GetPos`)가 없으면 행렬 합성과 `render`를 건너뛴다. 월드 타일 컬링과 같은 좌표 규격이고, 여유 한 칸은 타일 인덱스 반올림이 만드는 외곽과 같은 크기다.

```cpp
	RECT viewArea = camera->GetViewArea();
	InflateRect(&viewArea, TILESIZE, TILESIZE);

	for (UINT i = 0; i < (UINT)ObjType::END; ++i)
	{
		bool isStand = (i == (UINT)ObjType::Player || i == (UINT)ObjType::Monster);
		vector<Object*>::iterator iter = m_arrObj[i].begin();

		for (; iter != m_arrObj[i].end();)
		{
			Vec2D position = (*iter)->GetPos();
			if (position.x < viewArea.left || position.x > viewArea.right
				|| position.y < viewArea.top || position.y > viewArea.bottom)
			{
				++iter;
				continue;
			}

			if (isStand)
			{
				// 발을 축으로 피치를 되돌려 세운다: T(-Pos) · InversePitch · T(Pos) · ground
				...
				SetWorldTransform(hdc, &stand);
			}
			(*iter)->render(hdc);
			++iter;
		}
		SetWorldTransform(hdc, &ground);
	}
```

AABB(스프라이트 상자) 기준 컬링은 알면서 쓰지 않았다. 월드와 같은 점 + 여유 규격을 유지하기 위해서다. 렌더러나 렌더 컴포넌트라는 책임이 따로 있었다면 AABB를 택했을 것이다. 상자를 Object가 들게 되는 날 다시 본다.

### 소멸 책임 (컬링을 넣으며 같이 정리)

render 루프에 있던 `isDead` 판정과 `erase`는 제거했다. 목록 편집이 "그려졌는지"에 묶여 있어 일시정지·컬링에서 어긋났기 때문이다. 지금은 `EventMgr`가 `DELETE_OBJ`를 처리할 때 `SetDead` → `Scene::RemoveObj` → 보관, 다음 프레임 `delete`로 한 자리에서 끝낸다. `m_bisDead`는 인스턴스의 해제 대기 표시이고 update·render·충돌 모두에서 빠진다. 게임플레이 사망(쓰러지는 연출)은 별도 State로 만들 몫이다.

## 1. 원인 추적

변수를 하나씩 끄고 켰다. "변환 없음"과 "피치만"은 월드 버퍼에 배율 1로 그리고 BitBlt로 복사하므로 줌 휠이 화면에 영향을 주지 않는다.

| 조건 | 0 | 8 | −3 |
|---|---|---|---|
| 변환 없음 (피치 ×, 배율 ×) | 55fps | 54 | 56 |
| 배율만, 오브젝트별 | 36 | 30 | 48 |
| 피치만, 배율 없음 | 54 | 53 | 53 |
| 원본: 배율+피치 오브젝트별, DrawImage 쌍선형 | 32 | 18 | 47 |

| 관찰 | 근거 |
|---|---|
| 피치는 비용이 아니다 | 변환 없음과 피치만의 차이 1fps 안쪽 |
| 배율이 들어가는 순간 떨어진다 | 원본 프레임 32ms 중 오브젝트 25.8ms, 최대 줌 57ms 중 51.7ms. 지형은 어디서나 1.8ms |
| 행렬 연산은 무관하다 | 합성 0.03ms/프레임. Multiplier는 단위행렬의 스칼라배라 어디서 곱하든 같다 |
| PARGB 변환은 무관하다 | 로드 때 `PixelFormat32bppPARGB` 사본을 만들어 넘겨도 32 / 18 / 47 → 33 / 18 / 49fps |
| 보간이 원인이다 | `SetInterpolationMode(NearestNeighbor)` 한 줄로 32 / 18 / 47 → 90 / 82 / 97fps, 오브젝트 25.8 → 4.9ms |

픽셀당 비용으로 환산하면 GDI+ DrawImage 쌍선형 약 25~40ns, GDI+ 최근접 약 2.7ns, GDI AlphaBlend 약 1ns, GDI StretchBlt HALFTONE 전체 화면 약 6~10ns. 쌍선형의 산술이 비싼 것이 아니라 GDI+의 쌍선형 경로(범용 리샘플러, 벡터화 없음, DDB 목적지 읽기 왕복)가 비싸다. 순수 GDI+ 구성이었어도 사라질 비용은 아니다. 전체 화면 GDI+ 그리기를 DDB 대상에서 DIB 대상으로 바꿨을 때 300 → 127ms로 약 2.4배 차이였으니, HDC 혼용이 얹는 몫은 그 정도다.

## 4. 알파 픽셀 처리 (불투명 영역 경계 상자)

| 스프라이트 | 전체 | 불투명 영역 경계 상자 (Idle 첫 프레임) | 비율 |
|---|---|---|---|
| Wilson | 158×158 | 44×72 | 13% |
| Pigman | 106×106 | 52×65 | 30% |
| Spider | 122×122 | 58×31 | 12% |

쌍선형은 알파 0인 픽셀도 4픽셀을 읽어 섞은 뒤 버리므로, 비용의 70~88%가 안 보이는 픽셀에 쓰이고 있었다. 상자만 넘기면 그릴 영역이 그만큼 준다. 프레임마다 상자가 다르고(Wilson 43~44), 오프셋을 더해 그리므로 자리는 같다.

| | ① 쌍선형 | ② 최근접 | ③ AlphaBlend |
|---|---|---|---|
| 정사각형 전체 | 32 · 18 · 47 | 71 · 82 · 94 | 116 · 104 · 116 |
| 불투명 상자만 | 76 · 53 · 92 | 108 · 112 · 113 | 124 · 127 · 123 |
| 오브젝트 구간 ms (상자) | 6.9 · 12.9 · 4.4 | 2.4 · 2.4 · 2.0 | 1.5 · 1.4 · 1.3 |

픽셀당 비용이 큰 경로일수록 많이 번다. 쌍선형은 1/4, 최근접·AlphaBlend는 절반. 화질을 지키는 ①이 처음으로 예산 안에 들어왔다. 이것이 가장 먼저 했어야 하는 일이었다.

상자 비용: 텍스처당 RECT 16바이트, 첫 사용 때 158² 훑기 수십 µs(Wilson 927장 전부여도 합쳐 50ms 안팎, 첫 사용에 분산). 아틀라스 형식으로 리소스를 다시 묶을 때는 베이크 메타데이터로 옮기면 런타임 계산이 사라진다.

## 5. 결정

쌍선형 유지 + 불투명 상자. 사용자 11-05.

- 근거: GPU 백엔드 없는 고전 소프트웨어 게임의 기준(30/60fps)이면 화질을 지키는 쪽이 합리적이다.
- 결과: 기본 배치 76 · 53 · 92fps. 500마리 격자에서도 40~46fps로 줌과 무관하게 평평. 원본처럼 18fps까지 꺼지는 낙차는 사라졌다.
- 남은 비용은 화면을 덮는 스프라이트 픽셀 양에 비례한다. 픽셀당 비용 자체는 그대로이므로 화면이 빽빽하면 40fps대까지 내려간다. 그때는 6의 옵션을 켠다.
- 상자 적용 뒤 남는 바닥: UI 3.7ms, 지형 1.8ms, 창 복사 0.8ms. 다음 병목은 UI.

```cpp
	if (mode == SpriteDraw::AlphaBlend)

		HDC textureDC = currentFrameTex->GetDC();
		int width = (int)currentFrameTex->Width(), height = (int)currentFrameTex->Height();
		int boxWidth = box.right - box.left, boxHeight = box.bottom - box.top;
		BLENDFUNCTION blend = { AC_SRC_OVER, 0, 255, AC_SRC_ALPHA };
		AlphaBlend(hdc, (int)(vCenter.x - width / 2.f) + box.left, (int)(vCenter.y - height / 2.f) + box.top, boxWidth, boxHeight,
			textureDC, box.left, box.top, boxWidth, boxHeight, blend);
		return;
	}

	XFORM transform;
	GetWorldTransform(hdc, &transform);
	ModifyWorldTransform(hdc, nullptr, MWT_IDENTITY);
	{
		Graphics graphics(hdc);
		Matrix matrix(transform.eM11, transform.eM12, transform.eM21, transform.eM22, transform.eDx, transform.eDy);
		graphics.SetTransform(&matrix);
		if (mode == SpriteDraw::Nearest)
		{
			graphics.SetInterpolationMode(InterpolationModeNearestNeighbor);
		}

		Image* img = currentFrameTex->GetImage();
```

## 7. 제외한 방법

| 방법 | 측정 | 제외 이유 |
|---|---|---|
| 배율을 행렬에서 빼고 월드 버퍼(창÷줌)에 1배로 그린 뒤 마지막 `StretchBlt(COLORONCOLOR)` 한 번 | 57 · 98 · 54fps (오브젝트 11.0 · 3.9 · 11.4ms) | 효과가 그릴 픽셀 1/z²만큼이라 줌 1배 근처(−3단계, 버퍼가 창의 81%)에선 47 → 54에 그침. 버퍼 안은 여전히 쌍선형, 마지막 확대는 최근접이라 화질도 못 지킴. Core에 버퍼·Present, Scene에서 배율 제거 등 구조 변경. 원근(인스턴스별 배율)이 오면 전제가 깨짐 |

| 같은 구조, 마지막 한 번을 GDI+ `DrawImage` 쌍선형 | 3~4fps, present 300ms대 (최근접 80ms, DIB 백버퍼 127ms, PixelOffsetMode·FromHBITMAP 변형도 동일) | GDI+ 전체 화면 경로 자체가 실격 |
| 백버퍼 하나에 1배로 그리고 창 DC에 배율을 걸어 내보내기 | 55 · 61 · 53fps | UI가 백버퍼 밖에서 그려져 깜빡임(48프레임 중 3~9장 누락). 설계에 없던 안 |
| 줌 레벨별 미리 구운 텍스처 공유 | 계산만 | 프레임 수 × z². Wilson 927장만 최대 줌 1.17GB, 사용 묶음 전부 레벨당 2.4GB, 12레벨 수십 GB. 원근이 오면 인스턴스별 배율이 다시 곱해져 공유 불가 |

| 쌍선형 루프 직접 작성 | 미측정 | 샘플링·합성을 우리 코드로 가져오면 소프트웨어 렌더러. 범위 밖 |
| Direct2D 등 디바이스 백엔드 | 미측정 | 범위 밖(Win32API + CPU). 처음부터 짜는 건 CyphenEngine 몫 |

월드 버퍼 구조를 다시 꺼낼 일이 있으면 뼈대는 이렇다. Core에 `HBITMAP m_hWorldBit; HDC m_WorldDC; POINT m_worldSize;`를 두고, `GetWorldDC()`가 창÷배율 크기 비트맵을 만들어 뷰포트 원점을 가운데로 놓고 돌려주며, `PresentWorld(hdc)`가 `StretchBlt`로 백버퍼 가운데에 창 크기로 늘린다. `GameMgr::render`는 Scene을 월드 DC에 그리고 Present한 뒤 UI를 백버퍼에 그린다. Scene의 `ground`에서는 `Multiplier`를 뺀다.

## 8. 확인된 사실 (가설 정정)

- 피치 비용 ≈ 0. 행렬 합성 0.03ms. 배율을 앞에서 곱하나 뒤에서 곱하나 같다.
- PARGB 변환은 쌍선형 아래서 효과 없음.
- 화면 밖 스프라이트는 DC 클리핑이 버려 거의 공짜. 컬링은 호출 수(수백 개부터) 문제.
- 비싼 것은 쌍선형이 아니라 GDI+의 쌍선형 경로. 전체 화면 GDI+ 그리기는 어떤 설정으로도 80~300ms.
- 스프라이트 불투명 영역은 정사각형의 12~30%.
- 원작 Don't Starve는 이 문제를 GPU 샘플러로 푼다. 그 장치를 안 쓰기로 한 이상 답은 GPU 이전 세대의 것이다: 필터를 끄거나, 투명한 픽셀을 보내지 않는다.

## 9. 재현

측정 빌드는 삭제됐다. 다시 만들 때의 최소 구성이다. 전부 `_DEBUG`나 임시 브랜치에서 한다.

1. 케이스 스위치. 환경 변수(예: `DS_CASE`)를 `Core::init`에서 한 번 읽어 전역에 둔다. Scene은 그 값으로 `pitch`·`multiplier`를 identity로 바꾸고, Animation은 보간 모드·그리기 함수·상자 사용 여부를 바꾼다.
2. 구간 타이머. `QueryPerformanceCounter`로 행렬 합성 / 지형 / 오브젝트 / UI / 창 BitBlt / 프레임 전체를 누적하고, `TimeMgr`가 1초마다 fps를 낼 때 "`PROBE case= zoom= fps= matrix= terrain= objects= ui= blit= frame= drawn= culled=`" 한 줄을 표준 출력에 찍고 누적을 비운다. 콘솔은 `AttachConsole(ATTACH_PARENT_PROCESS)`로 붙인다.
3. 그린 수·건너뛴 수. Scene 컬링 분기에서 두 카운터를 올린다.
4. 격자 몬스터. `Scene_Start::Enter`에서 환경 변수(예: `DS_SPAWN`) 개수만큼 간격 250 격자에 Pigman/Spider를 번갈아 놓는다. 현재 원본에는 `_DEBUG` 상수 `debugSpawnCount`(500)로 들어 있다.
5. 절차. 전체 화면으로 띄우고 로딩 대기(500마리면 20초) → 0단계 6초 기록 → 휠 +8 → 6초 → 휠 −11 → 6초. 각 단계 마지막 4줄 평균. 지형·UI 구간이 평소(1.8 / 3.7ms)보다 1.5배 이상 높으면 경합이니 그 실행은 버린다.
6. 녹화. 창 사각형을 `Graphics.CopyFromScreen`으로 8fps 캡처해 PNG 연속으로 저장하고 GIF로 묶는다. 비교 캡처는 1920 원본에서 플레이어 주변 560×420을 1:1로 잘라 나란히 둔다.
7. 고정 조건. 같은 월드 시드, 같은 시작 배치, fps 글자는 기본 글꼴 한 줄로 전 케이스 동일.

```cpp
	{
		HBITMAP worldBit = CreateCompatibleBitmap(m_hdc, size.x, size.y);
		SelectObject(m_WorldDC, worldBit);
		DeleteObject(m_hWorldBit);
		m_hWorldBit = worldBit;
		m_worldSize = size;
	}
	SetViewportOrgEx(m_WorldDC, m_worldSize.x / 2, m_worldSize.y / 2, nullptr);
	return m_WorldDC;
}

void Core::PresentWorld(HDC hdc)
{
	SetStretchBltMode(hdc, COLORONCOLOR);
	SetBrushOrgEx(hdc, 0, 0, nullptr);
	StretchBlt(hdc,
		-(int)(m_ptWinInfo->right / 2), -(int)(m_ptWinInfo->bottom / 2), (int)m_ptWinInfo->right, (int)m_ptWinInfo->bottom,
		m_WorldDC,
		-(m_worldSize.x / 2), -(m_worldSize.y / 2), m_worldSize.x, m_worldSize.y,
		SRCCOPY);
}

// GameMgr::render: Scene을 월드 DC에 그리고 백버퍼에 Present한 뒤 UI
	HDC worldDC = Core::GetInst()->GetWorldDC();
	SceneMgr::GetInst()->render(worldDC);
	Core::GetInst()->PresentWorld(hdc);
	SetViewportOrgEx(hdc, 0, 0, nullptr);
	UIMgr::GetInst()->render(hdc);

// Scene::render: ground에서 Multiplier를 뺀다
	CombineTransform(&ground, &toLookAt, &pitch);
```

소멸자에서 `DeleteDC(m_WorldDC); DeleteObject(m_hWorldBit);`. 측정 당시 수치는 57 · 98 · 54fps, 스프라이트는 버퍼 안에서 쌍선형이었다.
